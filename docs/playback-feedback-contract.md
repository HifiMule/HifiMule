The proposed mapping must be checked using each source's current credentials and authenticated track read. A server brand, cached version, reporting capability, favorite browse flag, or response envelope alone does not qualify a write. A successful source read supplies a single exact-occurrence capability grant for at most 60 seconds, allowing durable local admission during a subsequent outage; the worker still verifies current version, account and capabilities before sending. A removed or reauthenticated account must not receive an older account's queued intent.

## Ordering and ambiguity policy

Operations freeze session, occurrence, portable source server, server-local track, authenticated account scope, requested value and operation ID before sending. The durable journal assigns monotonic source-track intent sequence numbers. Sends for one source track are serialized, and operation state is updated by operation ID; an old completion never confirms the latest intent.

The probes establish sequential set-value behavior, not cancellation or remote exactly-once execution. A successful response followed by a matching authoritative read can confirm an operation. A timeout, interrupted process, lost reply or unreadable post-write state is ambiguous. A later read establishes current remote state, not which client caused it. Automatic retry of uncertain writes is forbidden. Opposing work behind an uncertain send becomes conflict. A fresh read with an unchanged journal watermark and no pending/sending request records the observed value and reconciles these rows without sending any blocked opposite. The user must inspect that value and choose again when it differs from the latest desired intent. Do not infer that cancelling an HTTP future cancelled server execution. Navidrome starring is idempotent only at the Like/neutral level, not at the timestamp level.

Unknown and unavailable are distinct from neutral. Reconnect requires a fresh source read; cached intent cannot override another client's authoritative state. Session rejection is separate from all remote preference values and operation statuses.
